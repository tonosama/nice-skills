# Changelog 自動化



業界標準に沿った changelog 生成、リリースノート、バージョン管理を自動化するパターンとツールです。



## このスキルを使うタイミング



- 自動 changelog 生成をセットアップする場合

- Conventional Commits を導入する場合

- リリースノートのワークフローを作る場合

- コミットメッセージ形式を標準化する場合

- セマンティックバージョニングを管理する場合



## このスキルを使わないタイミング



- プロジェクトにリリースプロセスやバージョニングがない場合

- 一度きりの手動リリースノートだけが必要な場合

- コミット履歴が利用できない、または信頼できない場合



## 手順



- changelog 形式とバージョニング戦略を選ぶ。

- コミット規約またはラベルルールを強制する。

- ノートを生成・公開するツールを設定する。

- 正確性、網羅性、文言について出力をレビューする。

- 詳細な例が必要な場合は `resources/implementation-playbook.md` を開く。



## 安全性



- リリースノートにシークレットや社内限定の詳細を載せないこと。



## リソース



- 詳細なパターン、テンプレート、例は `resources/implementation-playbook.md`。



## アンチパターン



- 対象のテストスイートで検証せずにコード変更をデプロイしてはならない。

- 自明でないコードの前提、制約、副作用の文書化を省略してはならない。
