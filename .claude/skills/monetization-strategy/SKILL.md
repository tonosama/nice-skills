# Monetization Strategy

## Metadata
- **Name**: monetization-strategy
- **Description**: オーディエンス適合、リスク、検証実験を含む3〜5の収益化戦略をブレインストームする。収益モデルの探索、価格戦略の評価、ビジネスモデルオプションの検討時に使う。
- **Triggers**: monetization strategy, revenue model, pricing strategy, how to monetize, make money

## 手順

$ARGUMENTS 向けに収益化戦略をブレインストームする経験豊富なビジネスモデル戦略家として振る舞う。

プロダクトや機能に機能しうる3〜5の異なる収益化アプローチを策定し、ターゲット市場との適合を評価し、低コストの検証実験を概説する。

## 入力要件
- プロダクトまたは機能の説明
- ターゲット市場セグメントと顧客プロファイル
- 現行の支払意思または予算制約
- 競合の収益化アプローチ
- 会社の優先（収益成長、ユーザー成長、収益性）

## 収益化フレームワーク

各戦略について次を含める：

### 1. Strategy Name & Description
- 収益化モデルは何か？
- このプロダクトではどう機能するか？
- 誰が払い、何を得るか？

### 2. How It Works
- 収益モデルと価格メカニズム
- 企業と顧客の価値交換
- 支払頻度と取引規模
- ライフサイクルとリテンションの仕組み

### 3. Audience Fit
- なぜターゲット顧客に響くか？
- 顧客ニーズ・嗜好との整合は？
- 顧客に解く課題は？
- 対象市場規模と収益ポテンシャル

### 4. Unit Economics
- 推定 CAC
- 推定 LTV
- 損益分岐までのタイムライン
- 目標粗利率

### 5. Risks & Challenges
- 市場採用リスク
- 価格・機能への敏感度
- 競争上の脆弱性
- 顧客離脱・抵抗
- 実装の複雑さ

### 6. Competitive Position
- 競合はどう収益化しているか？
- 自アプローチの差別化は？
- 顧客スイッチの障壁
- 競合価格への防御

### 7. Validation Experiment
- 支払意思を検証する低コストテスト
- 手法: survey、landing page、pilot、freemium、waitlist
- 成功メトリクスと判断基準
- タイムラインと必要リソース

## 収益化戦略の例

### 1. Freemium（無料ベース + 有料プレミアム）
- **How**: コア無料、高度機能はペイウォール
- **Fit**: 大量・低タッチ向け（デザインツール、生産性、コミュニケーション）
- **Risks**: 低コンバージョン（通常1–5%）、アップグレード正当化に明確な機能差が必要
- **Experiment**: Freemium 版を立ち上げ、コンバージョン率とアップグレードフィードバックを追う

### 2. Subscription（月次／年次継続課金）
- **How**: 継続アクセス・更新の定期課金
- **Fit**: 継続的価値があるプロダクト（ソフトウェア、プラットフォーム、サービス）
- **Risks**: 顧客離脱、年次 vs 月次のカニバリゼーション
- **Experiment**: ベータ顧客にサブスク提供、離脱率と NPS を測定

### 3. Usage-Based（従量課金）
- **How**: 利用量に応じた課金（API calls、ストレージ、取引）
- **Fit**: B2B プラットフォーム、API、需要が変動するサービス
- **Risks**: 収益の予測困難、顧客のコスト不安、顧客による利用最適化
- **Experiment**: 利用トラッキングを実装、5–10 のベータ顧客でパイロット、収益モデル化

### 4. Enterprise/Seat-Based（ユーザー／シート単位）
- **How**: 利用ユーザー・部門・シートあたりの価格
- **Fit**: チーム・組織採用の B2B SaaS
- **Risks**: 営業複雑性、契約期間、実装オーバーヘッド
- **Experiment**: 5–10 の顧客インタビュー、シート単価の検証、サポートモデル定義

### 5. One-Time Purchase（買い切り）
- **How**: 永久または一回限りライセンスの一括購入
- **Fit**: ニッチツール・テンプレート（継続サービスではない）
- **Risks**: ローンチ期の収益集中、継続収益なし、更新・サポートの論点
- **Experiment**: 限定提供をローンチ、コンバージョンと顧客満足を追う

### 6. Marketplace/Transaction Fee
- **How**: 売買取引からの歩合または固定手数料
- **Fit**: 需給をつなぐプラットフォーム
- **Risks**: 流動性の鶏と卵、信頼と安全、競争圧力
- **Experiment**: 限定セラーで MVP、初期供給のため無料期間、ユニットエコノミクスモデル化

### 7. Advertising/Sponsorship
- **How**: 広告、スポンサー、ブランドパートナーシップからの収益
- **Fit**: 高トラフィックの消費者向けプロダクト
- **Risks**: 侵襲的広告によるブランド毀損、UX 悪化、広告主集中
- **Experiment**: 小セグメントで広告テスト、エンゲージメントと収益影響を測定

## 出力プロセス
1. 3〜5の異なる収益化戦略をブレインストーム（似たモデルの重複を避ける）
2. 各戦略について:
   - このプロダクト向けの具体的な仕組み
   - ターゲット顧客・支払意思との適合評価
   - 主要リスク・課題の概説
   - ユニットエコノミクス推定（CAC、LTV、タイムライン）
   - 競合アプローチとの比較
3. 各戦略について低コストの検証実験を設計
4. 次で優先:
   - 戦略的フィット（収益、成長、収益性目標）
   - 実装の容易さ
   - 市場検証の可能性
   - 競争優位
5. 最初に試す1〜2戦略を推奨
6. テストロードマップと成功基準を作成

## 戦略的考慮事項
- **Revenue Goals**: どれだけの収益が必要か？いつまでに？
- **Growth Goals**: 収益化はユーザー成長を支える必要があるか？
- **Market Dynamics**: 顧客は支払う用意があるか？何に対して？
- **Competitive Pressure**: 競合はどう反応するか？
- **Unit Economics**: 実現可能性に必要な粗利率は？

## 注意事項
- 最良の収益化は顧客価値と支払意思に整合する
- 早く頻繁にテスト；完璧なプロダクトを待たず価格を検証
- 多くのプロダクトはハイブリッド（Freemium + アップグレード、サブスク + マーケットプレイス手数料等）
- 価格は変えられる；顧客関係の再構築は難しい
- 競合は監視するが価格競争の底まで落ちない
