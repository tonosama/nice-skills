# Startup Financial Modeling

スタートアップ早期向けに、売上予測、コスト構造、キャッシュフロー分析、シナリオ計画を含む 3〜5 年の包括的財務モデルを構築する。

## このスキルを使うとき

- startup financial modeling のタスクやワークフローに取り組むとき
- startup financial modeling 向けのガイダンス、ベストプラクティス、チェックリストが必要なとき

## このスキルを使わないとき

- startup financial modeling と無関係なタスク
- このスコープ外の別ドメインやツールが必要

## 手順

- 目標、制約、必要な入力を明確にする。
- 関連ベストプラクティスを適用し成果を検証する。
- 実行可能な手順と検証を示す。

## 概要

財務モデリングは、スタートアップの戦略、資金調達、オペレーション計画の定量的基盤を提供する。コホートベースの売上モデル、詳細なコスト構造、シナリオ分析で現実的な予測を作り、意思決定と投資家向け資料を支える。

## コアコンポーネント

### 売上モデル

**コホートベース予測:**
顧客獲得とリテンションをコホート単位で積み上げて売上を構築する。

**式:**
```
MRR = Σ (Cohort Size × Retention Rate × ARPU)
ARR = MRR × 12
```

**主要入力:**
- 月次新規顧客獲得
- 月別顧客リテンション率
- ARPU（Average revenue per user）
- 価格・パッケージ前提
- 拡張売上（アップセル、クロスセル）

### コスト構造

**営業費用カテゴリ:**

1. **COGS（Cost of Goods Sold）**
   - ホスティングとインフラ
   - 決済手数料
   - カスタマーサポート（変動部分）
   - 顧客あたりの第三者サービス

2. **S&M（Sales & Marketing）**
   - CAC（Customer acquisition cost）
   - マーケプログラムと広告
   - 営業チーム報酬
   - マーケツールとソフトウェア

3. **R&D（Research & Development）**
   - エンジニアチーム報酬
   - プロダクトマネジメント
   - デザインと UX
   - 開発ツールとインフラ

4. **G&A（General & Administrative）**
   - 経営チーム
   - 財務、法務、人事
   - オフィスと設備
   - 保険とコンプライアンス

### キャッシュフロー分析

**構成要素:**
- 期首現金残高
- 現金流入（売上、資金調達）
- 現金流出（営業費用、CapEx）
- 期末現金残高
- 月次バーンレート
- ランウェイ（残存現金の月数）

**式:**
```
Runway = Current Cash Balance / Monthly Burn Rate
Monthly Burn = Monthly Revenue - Monthly Expenses
```

### 人員計画

**役割ベースの採用計画:**
部門・役割別に人員を追跡する。

**主要指標:**
- 従業員あたりフルコスト
- 従業員あたり売上
- 部門別人員（全体に占める割合）

**典型的な比率（早期 SaaS）:**
- Engineering: 40-50%
- Sales & Marketing: 25-35%
- G&A: 10-15%
- Customer Success: 5-10%

## 財務モデル構造

### 3 シナリオ・フレームワーク

**Conservative Scenario（P10）:**
- 顧客獲得が遅い
- 低価格または低コンバージョン
- 高いチャーン
- 営業サイクルが長い
- キャッシュ管理に使用

**Base Scenario（P50）:**
- 最もありそうな結果
- 現実的な前提
- 主計画シナリオ
- ボード報告に使用

**Optimistic Scenario（P90）:**
- 成長が速い
- 良いユニットエコノミクス
- 低チャーン
- アップサイド計画に使用

### 時間軸

**詳細予測: 3 年**
- Year 1 は月次
- Year 2 は月次
- Year 3 は四半期

**高レベル予測: Year 4-5**
- 年次予測
- 主要指標のみ
- 長期計画を支援

## ステップバイステップ手順

### Step 1: ビジネスモデルの定義

売上モデルと価格を明確化する。

**SaaS モデル:**
- サブスクリプション階層
- 年契約 vs 月契約
- 無料トライアルまたは freemium
- 拡張売上戦略

**Marketplace モデル:**
- GMV 予測
- テイクレート（取引の %）
- 買い手・売り手のエコノミクス
- 取引頻度

**Transactional モデル:**
- 取引量
- 取引あたり売上
- 頻度と季節性

### Step 2: 売上予測の構築

精度のためコホートベース手法を使う。

**月次新規顧客獲得:**
各月の新規顧客数を定義する。

**リテンションカーブ:**
時間経過による顧客維持をモデル化する。

**典型的 SaaS リテンション:**
- Month 1: 100%
- Month 3: 90%
- Month 6: 85%
- Month 12: 75%
- Month 24: 70%

**売上計算:**
各コホートで、各月の維持顧客数 × ARPU を計算する。

### Step 3: コスト構造のモデル化

カテゴリと性質別にコストを分解する。

**Fixed vs Variable:**
- Fixed: 給与、ソフトウェア、家賃
- Variable: ホスティング、決済、サポート

**スケーリング前提:**
- 売上に対する COGS %
- 売上に対する S&M %（CAC ペイバック）
- R&D 成長率
- 総費用に対する G&A %

### Step 4: 採用計画の作成

役割・部門別に人員増をモデル化する。

**入力:**
- 初期人員
- 役割別採用ペース
- 役割別フルコスト報酬
- 福利厚生・税（通常給与の 1.3-1.4 倍）

**例:**
```
Engineer: $150K salary × 1.35 = $202K fully-loaded
Sales Rep: $100K OTE × 1.30 = $130K fully-loaded
```

### Step 5: キャッシュフローの予測

月次の現金ポジションとランウェイを計算する。

**月次キャッシュフロー:**
```
Beginning Cash
+ Revenue Collected (consider payment terms)
- Operating Expenses Paid
- CapEx
= Ending Cash
```

**ランウェイ計算:**
```
If Ending Cash < 0:
  Funding Need = Negative Cash Balance
  Runway = 0
Else:
  Runway = Ending Cash / Average Monthly Burn
```

### Step 6: 主要指標の算出

ステージに応じた指標を追跡する。

**売上指標:**
- MRR / ARR
- 成長率（MoM, YoY）
- セグメントまたはコホート別売上

**ユニットエコノミクス:**
- CAC
- LTV
- CAC ペイバック期間
- LTV / CAC 比率

**効率指標:**
- Burn multiple（Net Burn / Net New ARR）
- Magic number（Net New ARR / S&M Spend）
- Rule of 40（Growth % + Profit Margin %）

**キャッシュ指標:**
- 月次バーンレート
- ランウェイ（月）
- キャッシュ効率

### Step 7: シナリオ分析

異なる前提で 3 シナリオを作る。

**変動前提:**
- 顧客獲得率（±30%）
- チャーン率（±20%）
- 平均契約額（±15%）
- CAC（±25%）

**固定前提:**
- 価格構造
- コア営業費用
- 採用計画（タイミング調整は可、役割は維持）

## ビジネスモデルテンプレート

### SaaS 財務モデル

**売上ドライバー:**
- New MRR（顧客 × ARPU）
- Expansion MRR（アップセル）
- Contraction MRR（ダウングレード）
- Churned MRR（離脱）

**主要比率:**
- 粗利率: 75-85%
- 売上に対する S&M %: 40-60%（早期）
- CAC ペイバック: 12 ヶ月未満
- Net retention: 100-120%

**予測例:**
```
Year 1: $500K ARR, 50 customers, $100K MRR by Dec
Year 2: $2.5M ARR, 200 customers, $208K MRR by Dec
Year 3: $8M ARR, 600 customers, $667K MRR by Dec
```

### Marketplace 財務モデル

**売上ドライバー:**
- GMV（Gross Merchandise Value）
- テイクレート（GMV の %）
- 純売上 = GMV × テイクレート

**主要比率:**
- テイクレート: カテゴリにより 10-30%
- 買い手 vs 売り手の CAC
- 寄与利益率: 60-70%

**予測例:**
```
Year 1: $5M GMV, 15% take rate = $750K revenue
Year 2: $20M GMV, 15% take rate = $3M revenue
Year 3: $60M GMV, 15% take rate = $9M revenue
```

### E-Commerce 財務モデル

**売上ドライバー:**
- トラフィック（訪問者）
- コンバージョン率
- AOV（Average order value）
- 購入頻度

**主要比率:**
- 粗利率: 40-60%
- 寄与利益率: 20-35%
- CAC ペイバック: 3-6 ヶ月

### Services / Agency 財務モデル

**売上ドライバー:**
- 請求可能時間またはプロジェクト
- 時間単価またはプロジェクト料金
- 稼働率
- チームキャパシティ

**主要比率:**
- 粗利率: 50-70%
- 稼働率: 70-85%
- 従業員あたり売上

## 資金調達連携

### 資金調達シナリオのモデル化

**Pre-Money バリュエーション:**
指標と比較事例に基づく。

**希薄化:**
```
Post-Money = Pre-Money + Investment
Dilution % = Investment / Post-Money
```

**資金使途:**
ランウェイ延長とマイルストーン達成に資金を配分する。

**例:**
```
Raise: $5M at $20M pre-money
Post-Money: $25M
Dilution: 20%

Use of Funds:
- Product Development: $2M (40%)
- Sales & Marketing: $2M (40%)
- G&A and Operations: $0.5M (10%)
- Working Capital: $0.5M (10%)
```

### マイルストーンベース計画

**主要マイルストーン:**
- プロダクトローンチ
- 初の $1M ARR
- CAC 損益分岐
- Series A 調達

**調達額:**
次マイルストーン + 6 ヶ月バッファのランウェイを確保する。

## よくある落とし穴

**落とし穴 1: 過度に楽観的な売上**
- 新規スタートアップは攻撃的予測に届きにくい
- 保守的な顧客獲得前提を使う
- 現実的なチャーンをモデル化する

**落とし穴 2: コストの過小見積もり**
- 費用見積もりに 20% バッファを足す
- フルコスト報酬を含める
- ソフトウェアとツールを計上する

**落とし穴 3: キャッシュフロー時期の無視**
- 売上 ≠ 現金（支払条件）
- 売上回収前に費用が支払われる
- キャッシュ転換を慎重にモデル化する

**落とし穴 4: 静的な人員計画**
- 採用には 3-6 ヶ月かかる
- 生産性ランプに 3-6 ヶ月
- 離職（年 10-15%）を考慮する

**落とし穴 5: シナリオ計画なし**
- 単一シナリオは正確になりにくい
- 常に保守シナリオをモデル化する
- ベースが外れた場合の対応を計画する

## モデル検証

**妥当性チェック:**
- [ ] 売上成長率が達成可能（Year 2 は 3 倍、Year 3 は 2 倍）
- [ ] ユニットエコノミクスが現実的（LTV/CAC > 3、ペイバック < 18 ヶ月）
- [ ] Burn multiple が妥当（Year 2-3 で < 2.0）
- [ ] 人員が売上に比例（従業員あたり売上が改善）
- [ ] 粗利率がビジネスモデルに適切
- [ ] S&M 支出が CAC と成長目標と整合

**ピアベンチマーク:**
同ステージの類似企業と主要指標を比較する。

**投資家フィードバック:**
アドバイザーや投資家に前提のフィードバックを得る。

## クイックスタート

スタートアップ財務モデルを作るには:

1. **ビジネスモデル定義** - 売上ドライバーと価格
2. **売上予測** - リテンション付きコホートベース
3. **コストモデル** - 月次で COGS、S&M、R&D、G&A
4. **人員計画** - 役割・部門別採用
5. **キャッシュフロー計算** - 売上 - 費用 = burn/ランウェイ
6. **指標算出** - CAC、LTV、burn multiple、ランウェイ
7. **シナリオ作成** - 保守、ベース、楽観
8. **前提検証** - 妥当性チェックとベンチマーク
9. **資金調達連携** - 調達ラウンドとマイルストーンをモデル化

完全テンプレートと式は `references/` と `examples/` を参照。

## Memory Sync

重要な技術的所見、アーキテクチャ判断、コードリファクタリング、リスク評価を終えたら、ローカル memory capture を**必ず**起動する。

1. 最終サマリーまたは成果物をプロジェクトディレクトリに Markdown で保存する。
2. capture スクリプトを実行する:
   ```bash
   python3 ~/memory_system/capture_knowledge.py <file_path>
   ```
3. 新しい学び、ポリシー、技術スニペットが適切なローカルストレージ（OKF または ChromaDB）へ自動ルーティングされる。
