# Transform Roadmap to Outcome-Focused Format

## Purpose

**$ARGUMENTS** が機能重視の成果物志向ロードマップから、顧客・ビジネスインパクトを強調するアウトカム志向ロードマップへ移行するのを、経験豊富な PM として支援する。イニシアティブを、重要なことをインスピレーションし測定できるアウトカム文に書き換える。

## Context

成果物志向ロードマップは誤った精度感を生み、チームを成果ではなく機能に揃えてしまう。アウトカム志向は解く顧客問題と期待するビジネス価値を明確にし、柔軟な実行と戦略的思考を可能にする。

## Instructions

1. **Gather Information**: 現行ロードマップがあれば精読。戦略文書や会社目標に言及があれば、ロードマップが広い目標とどう整合すべきかウェブ検索で把握。

2. **Think Step by Step**:
   - 各イニシアティブについて: 「達成したいアウトカムは何か？」
   - 解く顧客問題は？
   - 改善するビジネス指標は？
   - 顧客体験やビジネスへの影響は？
   - 同じアウトカムを達成する別のよりよい方法はあるか？

3. **Transformation Process**: ロードマップ上の各イニシアティブについて:
   - **Identify the Output**: 計画されている機能またはプロジェクトは？
   - **Uncover the Outcome**: なぜ作るか？ 顧客・ビジネスに何が変わるか？
   - **Rewrite as Outcome Statement**: 次の形式:
     ```
     Enable [customer segment] to [desired customer outcome] so that [business impact]
     ```

4. **Example Transformation**:
   - **Output (Old)**: Q2: Build advanced search filters, implement AI recommendations, redesign dashboard
   - **Outcome (New)**:
     - Q2: Enable customers to find products 50% faster through intuitive discovery
     - Q2: Increase average order value by 20% through personalized AI recommendations
     - Q2: Help operators monitor all systems with 80% reduction in dashboard load time

5. **Structure Output**: 変換後ロードマップを提示:
   - 四半期/フェーズ別の元イニシアティブ
   - 各イニシアティブのアウトカム文
   - 成功を示す主要指標
   - 依存関係や順序のメモ

6. **Include Strategic Context**: ロードマップ全体に:
   - アウトカムが会社戦略とどう整合するか
   - 顧客ニーズに関する主要仮定
   - 柔軟なリリースウィンドウ（四半期、具体日付ではない）

7. **Save the Output**: 分量が大きければ Markdown: `Outcome-Roadmap-[year].md`

## Notes

- アウトカムは検証・測定可能であること
- 1つのアウトカムに複数の成果物がありうる。機能リストではなくアウトカムに焦点
- アウトカムロードマップは変更に強い — 柔軟性を受け入れる
- 機能がどんなアウトカムを駆動するか不明なら「So what?」を繰り返し、本当の顧客/ビジネス価値まで至る
