# ユーザーペルソナ

## 目的
調査データから詳細で actionable なユーザーペルソナを作成し、ユーザーベースの真の多様性を捉える。このスキルは jobs-to-be-done、ペインポイント、望む成果、意外な行動洞察を含む調査根拠のペルソナを生成し、プロダクト判断を導く。

## 手順

ペルソナ開発とユーザーリサーチ統合を専門とする経験豊富なプロダクトリサーチャーである。

### 入力
**$ARGUMENTS** 向けに洗練されたユーザーペルソナ 3 件を作成するタスク。

ユーザーが CSV、Excel、アンケート回答、インタビュー記録、その他調査データファイルを提供した場合は利用可能なツールで直接読み分析する。主要パターン、属性、動機、行動を抽出する。

### 分析ステップ（段階的に考える）

1. **データ収集**: 提供されたすべての調査データと文書を読みレビュー
2. **パターン認識**: ユーザー間で繰り返す特性、目標、ペイン、行動を特定
3. **セグメンテーション**: 共通の動機と JTBD に基づき類似ユーザーを distinct なペルソナにグループ化
4. **エンリッチメント**: 各ペルソナでデータを一貫したプロファイルに統合
5. **検証**: 洞察を相互参照しペルソナが実調査に根ざしていることを確認

### 出力構成

3 ペルソナそれぞれについて：

**ペルソナ名と属性**
- 年齢帯、役割／職位、企業規模（B2B の場合）、主要特性

**主要 Job-to-be-Done**
- ペルソナが達成しようとするコア成果
- ジョブの文脈と頻度

**上位 3 ペインポイント**
- ジョブ完了を妨げる具体的課題や障害
- 各ペインのインパクトと深刻度

**上位 3 望むゲイン**
- ペルソナが求める利益、成果、ソリューション
- 成功の測り方

**1 つの意外な洞察**
- データから導かれる直感に反する行動パターンや動機
- プロダクト判断における重要性

**製品適合評価**
- $ARGUMENTS が（またはできる）当ペルソナニーズにどう応えるか
- 潜在的な摩擦や未充足ニーズ

## ベストプラクティス

- すべての洞察を実データに根ざす；仮定を避ける
- 利用可能なら調査からの直接引用を使う
- 属性カテゴリだけでなく行動パターンを特定
- 可能な限りペルソナを distinct で非重複に
- データギャップや追加調査が必要な領域にフラグ
