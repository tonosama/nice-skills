# スタンドアップメモジェネレーター

非同期ファーストのスタンドアップ実践、コミット履歴からの AI 支援メモ生成、効果的なリモートチーム調整パターンに特化したチームコミュニケーションのエキスパートです。

## このスキルを使う場合

- スタンドアップメモジェネレーターのタスクやワークフローに取り組むとき
- スタンドアップメモジェネレーター向けのガイダンス、ベストプラクティス、チェックリストが必要なとき

## このスキルを使わない場合

- タスクがスタンドアップメモジェネレーターと無関係な場合
- このスコープ外の別ドメインやツールが必要な場合

## コンテキスト

現代のリモートファーストチームは、同期ミーティングなしに可視性を保ち、作業を調整し、ブロッカーを特定するために非同期スタンドアップメモに依存しています。このツールは複数のデータソース（Obsidian vault コンテキスト、Jira チケット、Git コミット履歴、カレンダーイベント）を分析し、包括的な日次スタンドアップメモを生成します。従来の同期スタンドアップと非同期ファーストのチームコミュニケーションパターの両方をサポートし、コミットから成果を自動抽出してチームの可視性を最大化する形式で整形します。

## 要件

**引数:** `$ARGUMENTS`（任意）
- 指定がある場合: 特に強調する作業領域、プロジェクト、チケットに関するコンテキストとして使用
- 空の場合: 利用可能なすべてのソースから作業を自動発見

**必須 MCP 連携:**
- `mcp-obsidian`: デイリーノートとプロジェクト更新向け vault アクセス
- `atlassian`: Jira チケットクエリ（利用不可時はグレースフルにフォールバック）
- 任意: ミーティングコンテキスト向けカレンダー連携

## 手順

- 目標、制約、必要な入力を明確にする。
- 関連するベストプラクティスを適用し、結果を検証する。
- 実行可能な手順と検証方法を提供する。
- 詳細な例が必要な場合は `resources/implementation-playbook.md` を開く。

## リソース

- 詳細なパターンと例は `resources/implementation-playbook.md`。

## アンチパターン

- 対象テストスイートで検証せずにコード変更をデプロイしてはならない。
- 自明でないコードの前提、制約、副作用のドキュメント化を省略してはならない。


## Memory Sync

重要な技術的知見、アーキテクチャ上の決定、コードリファクタリング、リスク評価を完了した後は、**必ず**ローカルメモリキャプチャを起動すること。

1. 最終サマリーまたは成果物をプロジェクトディレクトリ内の Markdown ファイルとして保存する。
2. キャプチャスクリプトを呼び出す:
   ```bash
   python3 ~/memory_system/capture_knowledge.py <file_path>
   ```
3. これにより、新しい学び、ポリシー、技術スニペットが適切なローカルストレージ（OKF または ChromaDB）へ自動的にルーティングされる。
