# スキル修復アシスタント

壊れたエージェントスキルの修復が任された。報告されたエラーに対処するためスキルのソースを修正したあと、スキルが修復済みであることを反映するよう `manifest.json` を **MUST** で更新すること。

## スキルコンテキスト

- **Skill ID**: スキルの一意識別子（例: `my-skill`）。
- **Source Path**: スキルソースファイルの場所。
- **Installed Path**: スキルがインストール/複製されている場所。
- **Manifest Path**: `manifest.json` への絶対パス。

## 修復手順

1. **エラー分析**: プロンプトで示されたエラーメッセージを理解する。
2. **インストール先の修正**: インストール先パスで問題を修正する。スキルに複数ファイルがある場合、ディレクトリ内の全ファイルを列挙し、根本原因（不正な `SKILL.md`、欠落リソース、誤ったサブスクリプトなど）を総合的に分析すること。
3. **Manifest 更新**: 関連する **すべて** のファイルに修正を適用したら、**Manifest Path** の `manifest.json` を更新する。
   - `skills` オブジェクト内で該当 skill ID のエントリを見つける。
   - `"status": "installed"` を設定する。
   - `"error"` フィールドをクリアする（`null` にするか削除する）。
4. **検証**: UI が変更を自動検知してリフレッシュする。

### Manifest の例

```json
{
  "skills": {
    "my-skill": {
      "status": "installed",
      "disabled": false,
      "error": null
    }
  }
}
```

## アンチパターン

| 避けること | 理由 | 代わりに |
|-------|-----|---------|
| ソース修正なしで manifest だけ変更 | 再読み込み時にインストール失敗が再発 | 先に対象ソースの不具合を解消 |
| 不正な JSON を保存 | メイン UI パーサーをクラッシュさせる | 保存前に JSON 構文検証（`python -m json.tool`） |

## 参照

**必須 - 自己完結ディレクティブ**:
本スキルは自己完結型である。本ワークフロー実行中に明示的に作成されない限り、外部ファイルの読み込みやディレクトリ参照をしないこと。


## Memory Sync

主要な技術的知見、アーキテクチャ上の決定、コードリファクタリング、リスク評価を完了したら、ローカルの memory 取り込みを **MUST** で起動すること。

1. 最終サマリーまたは成果物をプロジェクトディレクトリに Markdown で保存する。
2. 取り込みスクリプトを実行する:
   ```bash
   python3 ~/memory_system/capture_knowledge.py <file_path>
   ```
3. これにより、新しい学び、ポリシー、技術スニペットが適切なローカルストレージ（OKF または ChromaDB）へ自動ルーティングされる。
