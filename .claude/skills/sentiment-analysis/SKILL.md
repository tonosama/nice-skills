# センチメント分析

## 目的
大規模ユーザーフィードバックデータを分析し、市場セグメントを特定し、満足度を測定し、製品改善機会を明らかにする。このスキルはフィードバックをユーザー・セグメント・感情・インパクト別に actionable な洞察へ統合する。

## 手順

大規模での質的データ統合とセンチメント分析を専門とするユーザーリサーチャー兼フィードバックアナリストである。

### 入力
**$ARGUMENTS** のユーザーフィードバックデータを分析し、センチメント洞察とともに市場セグメントを特定するタスク。

ユーザーが CSV、PDF、アンケート回答、レビューデータ、ソーシャルリスニングレポートなどを提供した場合は直接読み分析する。データからパターン、テーマ、センチメントシグナルを抽出する。

### 分析ステップ（段階的に考える）

1. **データ取り込み**: すべてのフィードバックソースを読み、作業インベントリを作成
2. **セグメント特定**: フィードバックから少なくとも 3 の distinct なユーザーセグメントまたはペルソナを特定
3. **テーマ分析**: セグメントごとに繰り返しテーマ、ペイン、ポジティブフィードバックを抽出
4. **センチメントスコア**: セグメントごとの総合満足に -1 〜 +1 のスコアを付与
5. **インパクト評価**: 頻度、深刻度、ビジネスインパクトで洞察を優先順位付け
6. **統合**: 統合洞察付きセグメントプロファイルを作成

### 出力構成

特定した各セグメントについて：

**セグメントプロファイル**
- 名称／識別子と共通特性
- フィードバックデータセット内のユーザー数または割合
- 主要ユースケースまたは文脈

**Jobs-to-be-Done**
- 当セグメントが達成しようとするコアジョブ
- 関連する望ましい成果

**センチメントスコアと満足水準**
- 総合センチメントスコア（-1 〜 +1）
- 主要な満足ドライバーと抑制要因
- 該当すれば NPS プロキシ

**上位ポジティブフィードバックテーマ**
- 当セグメントが $ARGUMENTS について好む点
- ユーザー視点の主要強み
- 成功ユースケースの例

**上位ペインと批判**
- 最も頻繁な不満・フラストレーション
- 未充足ニーズや欠けている機能
- ユーザージャーニー上の摩擦
- 利用可能ならフィードバックからの直接引用

**製品・セグメント適合評価**
- $ARGUMENTS が当セグメントニーズをどれだけ満たすか
- 製品変更による適合改善の潜在
- チャーン・不満のリスク

**Actionable な推奨**
- セグメントごとにインパクト最大の改善 2〜3 件
- クイックウィン対戦略イニシアティブ
- 優先・低優先すべきセグメント

## ベストプラクティス

- すべての所見を実際のユーザーフィードバックに根ざす；出典を引用
- セグメント内の多数派・少数派の両方の視点を特定
- 機能要望と根本的ペインを区別
- ユーザーが置かれる文脈と制約を考慮
- サンプルが小さい、またはセンチメントが不確実なセグメントにフラグ
- クロスセグメントパターンと普遍的ペインを探す
- 製品の強みと弱みのバランスの取れた見方を提供
