# 最低限調査チェックリスト（Minimum Discovery）

| 項目 | 内容 |
|---|---|
| 版 | 0.2 |
| 更新日 | 2026-11-15（Asia/Tokyo） |
| 方針 | **全面現状分析はしない**。パイロット可否に必要な項目だけ埋める |
| 関連 | [ソフトウェアアーキテクト方針](./software-architect-policy.md) |

**凡例**: `[ ]` 未着手 / `[~]` 進行中 / `[x]` 完了 / `N/A` 対象外  
**粒度**: 完璧な正確さより、「粗いが意思決定できる」で打ち切る。

---

## 使い方

1. **必須（MUST）**だけを短時間で埋める  
2. 不明は「不明」＋「パイロットで学ぶ／後で調べる」と書く  
3. **後回し（DEFER）**は触らない（必要になったスライスで開く）  
4. MUST が埋まったら方針書を確認し、パイロットへ進む

## Phase 0 完了ゲート（MUST のみ）

- [ ] M1〜M6 が「粗い答え」または「不明＋学び方」で埋まっている  
- [ ] パイロット候補が **1 つ**決まっている（2 つ目は任意）  
- [ ] 「全面 As-Is は今はやらない」が関係者に共有されている  
- [ ] パッケージ戦略は当面 **A（核は残し、周辺を外出し）** で開始する合意（変更は ADR）  

完了後、方針書の成功指標・候補欄を更新する。

---

## DEFER — 後回し（今はやらない）

必要になったスライス／フェーズで開く。**Phase 0 の完了条件に含めない。**

| 領域 | 後回し例 | いつ開くか |
|---|---|---|
| チャンク全体 | 全チャンク一覧・全依存図 | 2 本目以降で境界が曖昧なとき |
| アプリ全体 | 全スタック・全連携の棚卸し | パイロットが触る範囲だけ都度 |
| Oracle 全体 | 全スキーマ、全 PL/SQL、精密サイズ | 脱 Oracle を本流にするとき |
| 性能全体 | 全ボトルネック調査 | パイロットまたはピーク問題が出たとき |
| インフラ全体 | 全サーバ台帳、DR 詳細 | クラウド土台設計に入るとき |
| 組織全体 | 全スキルマップ | 体制がボトルネックになったとき |

旧版の詳細項目が必要なら、そのときこの節に戻して必要な行だけ復活させる。
